Le 30/09/2026, sur demande explicite de l'utilisateur, l'onglet "Sacrifice" du Codex a été entièrement refait après une série de sessions de code (Zgrubulu) qui ont designé et implémenté les 24 cartes définitives du pilier (6 classes × 4 catégories : Mise à mort/Legs/Héritage/Écho), classe par classe. Ce n'est plus "moteur implémenté + contenu générique en attendant mieux" (état de la 6ᵉ session du 28/09, voir `project_pilier-sacrifice-proposition.md` pour l'historique complet) : le contenu est désormais réel, définitif, et l'onglet est traité comme un onglet normal.

**Ce qui a changé dans le Codex** :
1. Relecture fraîche complète de `game/src/data/cards.lua` (les 30 défs Sacrifice/Legs/Héritage/Écho, avec leurs commentaires de conception très détaillés et datés), `game/src/data/glossary.lua` (7 mots-clés du pilier : Mise à mort, Héritage, meurt, Permanent, Survie, Exaltation, Vol de Vie), `game/src/rules/game.lua` (`Game.kill_hero`, `process_hero_deaths`, `convert_remaining_cards_to_echo`, `grant_permanent_buff`, `grant_camouflage`, `gain_discretion`), `game/src/rules/combat.lua` (`effective_owner`, `can_play`, `deal_damage`/survie), `game/src/rules/draft.lua` (exclusion permanente par run des cartes "Mise à mort" déjà draftées, `state.run.drafted_mise_a_mort`), `spec/sacrifice_spec.lua` (couverture exhaustive, confirme chaque comportement classe par classe).

**Écarts/incohérences repérés en relisant le code (signalés dans le Codex ET à l'utilisateur), rien de caché** :
- Le **Barde** est un cas hybride non anticipé par le brouillon d'origine : sa carte "Mise à mort" (Célébration Finale) cible un allié (comme les 3 cartes fratricide) mais c'est le LANCEUR qui meurt (comme les auto-sacrifices) — il choisit juste qui reçoit le bénéfice "Survie". Confirmé par relecture directe de l'effet (`Game.kill_hero(ctx.state, ctx.hero, true)` alors que `ctx.target` reçoit juste le buff).
- La règle de brainstorming "auto-sacrifice → l'effet immédiat va à un allié choisi" n'est PAS respectée pour Guerrier (dégâts de zone à tous les ennemis) ni Paladin (annule toutes les actions ennemies) — bénéfice d'équipe généralisé, pas un allié désigné. Seul le Barde suit vraiment cette règle. Le côté fratricide (bénéfice systématique au lanceur) est, lui, respecté à 100% (Assassin/Mage/Nécromancien).
- Pour l'Assassin et le Nécromancien, le Legs est un simple effet INSTANTANÉ (pas "Permanent") alors que l'Héritage correspondant EST "Permanent" — vraie différence de nature entre paliers, pas juste de force. Pour Guerrier/Paladin/Barde/Mage, Legs ET Héritage sont tous deux "Permanent" (valeurs différentes seulement).
- Le glossaire séparé du Codex (onglet "Glossaire", `docs/design/glossaire.md`) n'avait PAS été mis à jour avec les 7 mots-clés du pilier (Mise à mort, Héritage, meurt, Permanent, Survie, Exaltation, Vol de Vie) au moment de cette reconstruction de l'onglet Sacrifice — **corrigé le jour même dans une passe dédiée**, voir `project_glossaire-synchronise-pilier-sacrifice.md`.
- Règle confirmée et non ambiguë (déjà annoncée par l'utilisateur, vérifiée dans le code) : "Mise à mort" impose toujours l'Héritage à qui MEURT, jamais le Legs, y compris pour les 3 cartes fratricide où c'est un ALLIÉ tué par le lanceur (pas un auto-sacrifice) — `Game.kill_hero(ctx.state, ctx.target, true)`, le `true` (voluntary) est posé sur la victime quel que soit qui a joué la carte.
- Axe "l'Élu" (`heritage_count`) : toujours un compteur visuel pur, aucun effet de jeu — statu quo par rapport à la session précédente, toujours volontairement laissé de côté.

**Pourquoi** : l'utilisateur a explicitement requalifié ce pilier de "système livré" (plus une proposition) — le traitement documentaire bascule donc du régime d'exception (bandeaux de validation, pas de fichier `.md`) au régime normal de toute reconstruction agent_doc.

**Comment l'appliquer** : pour toute future demande sur ce pilier (ajouter une carte, corriger un effet, documenter un rééquilibrage), repartir de `docs/design/sacrifice.md` déjà reconstruit + une relecture ciblée du code concerné, comme pour `cartes.md`/`ennemis.md` — plus un audit complet à chaque fois. Si l'utilisateur demande explicitement la mise à jour du Glossaire pour ces mots-clés, c'est une passe distincte (onglet Glossaire + `docs/design/glossaire.md`), pas une simple relecture de l'onglet Sacrifice.
