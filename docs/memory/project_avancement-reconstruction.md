**Note d'outillage — republier un Artifact volumineux (avec images base64) après une session précédente** : l'action `Artifact action:"read"` sauvegarde le HTML complet dans un fichier local temporaire ; éditer CE fichier avec `Edit` (pas besoin de le régénérer de zéro) puis `publish` dessus. Si `publish` est refusé avec "n'a pas été vu en entier", c'est que l'outil exige d'avoir *réellement* relu (via `Read`, ligne par ligne si nécessaire) l'intégralité du fichier sauvegardé — y compris la ligne 1 (souvent un unique très long minified JS de runtime) — avant d'accepter la publication, même si ce fichier a déjà été lu une fois plus tôt dans la session. Une seule ligne contenant des images en `data:` base64 peut à elle seule dépasser le budget de tokens d'un appel `Read` (~25k) : il faut alors relire par petits `limit` (1-2 lignes) autour des lignes lourdes. Si `publish` est refusé une 2ᵉ fois en disant que le contenu envoyé est "identique à une version déjà refusée", refaire un `Artifact action:"read"` pour re-confirmer la version live avant de republier.

**Pourquoi :** évite de refaire un audit complet du code à chaque nouvelle demande — on repart des .md déjà reconstruits + une relecture ciblée du code concerné.

**Comment l'appliquer :** au début de toute future session agent_doc, lire ce fichier pour savoir quels documents existent déjà et où en est la reconstruction, avant de proposer un plan.
